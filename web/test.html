Proposta · r1

Uma console de acesso seguro que parece profissional.

Quatro eixos: paletas intercambiáveis (Azure, Evergreen, Ember, Iris — cada uma com claro + escuro), profundidade em camadas que elimina as linhas de marcação, tipografia com propósito e uma sessão unificada: identidade, estado e bloqueio automático no mesmo cartão, com contagem regressiva viva.

tokens puros

Sem uma cor ou pixel hardcoded: tudo consome --color-*, --gap-*, --radius-*. Trocar de paleta é reescrever só o bloco de tokens — exatamente como pede docs/okf/concepts/theming.md.

CSP-compatível

Esta página roda sob a mesma Content-Security-Policy do app real: zero CSS/JS inline, zero CDN. O que funciona aqui é diretamente implementável em style.css.

Eixo 2 · Tipografia

Space Grotesk para títulos, Inter para o corpo, JetBrains Mono para números e chaves

O produto é uma console técnica: títulos geométricos e compactos, texto neutro e legível, e tudo que é identificador (npub, URL, RTT, telemetria) em mono com dígitos tabulares — valores param de "dançar" quando atualizam. Na implementação os woff2 são self-hosted em web/vendor/fonts/ (~45 KB subsets latin, CSP proíbe CDN); sem os arquivos, o fallback de sistema mantém o ritmo da escala.

Como isso vira o app real

  1. Escolher 1 paleta padrão acima (mantendo as demais como opção futura de tema no toggle).
  2. Portar os tokens + elevação para web/style.css (mesmos nomes de classe → diff pequeno).
  3. Fundir #vault-section + KPI "Sessão" + #auto-lock-section no novo cartão de sessão; countdown alimentado por SessionManager.
  4. Self-host dos woff2 em web/vendor/fonts/ (subsets latin, font-display: swap).
  5. Remover test.html/test.css/test.js e atualizar docs/okf/concepts/theming.md + web-frontend-layout.md.

Nada aqui toca o protocolo, o CSP ou as dependências; é 100% camada de apresentação.
